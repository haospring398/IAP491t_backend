## PhishingEmailDetection

Python email-classification pipeline using Doc2Vec and 134 engineered features (upstream v6 code, merged 2026-11-07), plus a local web demo in web/ (Next.js frontend, Python backend) serving one pinned schema-2 run (since 2026-11-04 the upstream baseline_v6 run; validation selected MLP, but the web serves the run's explicitly pinned XGBoost at its own validation threshold, so each result carries its label and the exact per-result factor explanation, AD-14). web/ runs standalone (copied without the rest of the repository) once a run is bundled into web/model/.
Read README.md for setup. BMad planning artifacts belong in _bmad-output/; web/docs/ holds synced snapshots of them.

## Policy

- Never modify, move or delete Dataset/, paper/, model/ (the root folder; web/model/ is the git-ignored bundle that web/scripts/bundle-run.py rewrites), existing runs in runs/, or the legacy web run dumped_models/classification/runs/<run-id>/ (selected by current.json, no longer served). Write each new training/evaluation run to a new runs/<YYYY-MM-DD_name>/ folder.
- Write README content, code comments and commit messages in Vietnamese. Keep web UI copy in English (required by the SPEC) and BMad documents in English (_bmad/config.toml).

## Where things are

- Change corpus loading in load_data.py and feature extraction in preprocess.py.
- Trace training through train.py and artifact verification/publication through artifact_store.py; evaluation through evaluate.py.
- Use analyze_feature_importance.py to investigate reliance on dataset-source features.
- Measure per-dataset contribution with dataset_ablation.py (spec _bmad-output/implementation-artifacts/spec-dataset-ablation.md). It reads a `train.py --features-only` export, removes or keeps one dataset group in train and validation (groups: nazario, phishing_pot, epvme, malspam; enron, spamassassin, trec, ceas, ling; an unknown Source stops it), retrains Doc2Vec and the 9 classifiers through train.py's own functions under PYTHONHASHSEED=0 (self re-exec), and scores all 18 experiments (including without_enron_trec and a group-stratified random control that never draws clusters above 5% of its target) on the identical full test split. Each experiment writes runs/<...>/<experiment>/ with a lock file and resumes (the resume key includes epochs and PYTHONHASHSEED; a failed experiment is recorded and the queue continues, a definition mismatch stops the queue, and an experiment whose code files changed after the process started is refused); it writes only to a new folder or one holding ablation.json for the same export; no model pickles, only test scores. `--list` and `--overlap` need no training; `--summarize` builds the summary CSVs and heatmaps.
- web/backend/adapter.py serves the schema-2 run pinned by RUN_PATH in web/backend/policy.py or the IAP_WEB_RUN_PATH environment variable; both resolve relative paths from web/, not the project root (currently model/2026-11-02_baseline_v6, a bundle of runs/2026-11-02_baseline_v6: upstream runs/baseline_v6 of commit 867316b, trained by upstream a202d55 code, downloaded from Git LFS on 2026-11-04 with every manifest hash verified; 234 columns = Doc2Vec 100 + 134 preprocess.BASELINE_FEATURE_NAMES, signature 4c010fc3…, selected MLP). The served classifier is pinned by MODEL_NAME in web/backend/policy.py ("XGBoost") or the IAP_WEB_MODEL environment variable (inherited by the spawned worker); the value `selected` (or MODEL_NAME None with no variable) serves the manifest's selected_model instead. The name must exist in manifest["models"] and pass the selected-model checks (sklearn kind, plain file name, threshold in [0, 1], controlled unpickling, widths, classes), else the worker is unready at MODEL_COMPATIBILITY; it is served at its own manifest threshold (XGBoost 0.2113690823…; FP 1292 / FN 76 on the bundled test arrays), and worker metadata records both selected_model and served_model. Bundle a run with the stdlib-only `python web/scripts/bundle-run.py --run runs/<...>`: it verifies every manifest hash while copying the manifest and its artifacts into web/model/<run-id>/ through a temporary folder (no NLTK data since v6). web/model/ is git-ignored (about 1.2 GB), so a clone must re-run the script; copying web/ carries it. The backend uses package-relative imports (`python -m backend` from web/ or `python -m web.backend` from the root) and never imports root modules at runtime or in tests; web/backend/requirements.txt pins the whole backend (installs cleanly into web/.venv, Python 3.11.16 created with `uv python install 3.11.16` and `uv venv .venv --python 3.11.16 --seed` in web/, and matches the root .venv, Python 3.11.2) and must start with its `# -*- coding: utf-8 -*-` line, because pip 22 otherwise decodes the Vietnamese comments with cp1252. The backend does not import the root preprocess.py and pipeline_cache.py: web/backend/__init__.py puts web/backend/frozen_pipeline/ first on sys.path, and that folder holds byte-exact copies of the upstream a202d55 code that trained the pinned run (preprocess.py with CRLF line endings, sha256 51a4d22c…, as hashed at training; pipeline_cache.py LF, sha256 1f744d8c…), so editing the root pipeline never affects the web. Since the 2026-11-07 merge the root preprocess.py and pipeline_cache.py have the same content as these copies, but the signature also hashes line-ending bytes: the root .gitattributes pins both root files to LF (like the a202d55 blobs, regardless of core.autocrlf), so root-trained runs get a different signature than the pinned run and the web needs the LF copies in frozen_pipeline/ to serve them. The adapter uses private names from them (_parse_email, _safe_decode, _english_stopwords, reset_extraction_stats, infer_document_vector, _process, preprocessing_signature) plus BASELINE_FEATURE_NAMES and baseline_feature_vector, requires magika, oletools and tldextract at startup (DEPENDENCY_LOAD), and rejects runs whose recorded preprocessing signature, stopwords or feature list differs or that lemmatize; the signature hashes the copies' bytes, so never edit or reformat them (web/.gitattributes disables line-ending conversion there). To serve another run, replace both copies with byte-exact copies of the files that trained it, adapt the adapter if its feature list differs, bundle the run, re-pin RUN_PATH to model/<run-id>, regenerate the test fixture and run the web backend tests. The web backend tests use the committed fixture run web/backend/tests/fixture_run/ (about 220 KB, XGBoost and MLP with MLP selected; the tests serve the pinned XGBoost and set IAP_WEB_MODEL=selected for label-only cases; web/.gitattributes also marks it -text, because core.autocrlf is true here and the manifest hashes its bytes, CSVs included). Regenerate it with `web/.venv/Scripts/python.exe web/backend/tests/build_fixture.py` from the root: it builds the run directly from the frozen _process/baseline_feature_vector (no root import) with PYTHONHASHSEED=0, because Doc2Vec vectors depend on the hash seed and the worker child uses 0. Serve the demo with web/.venv: upstream extracted the v6 features in a Debian 12 sandbox (Python 3.11.2 per its README), most likely with Debian's backported strict email.utils.getaddresses (CVE-2023-27043), which python.org 3.11.2 in the root .venv lacks and 3.11.16 has. On 250 local test emails, root .venv matched data_X_test exactly for 192 engineered vectors (worst difference 13.2) and web/.venv for 199 (worst 0.43); all 250 MLP labels agreed in both, and all 250 served XGBoost labels agreed on web/.venv (remeasured 2026-11-04). The remaining 51 differ only in body statistics because upstream's extracted copies lack one trailing newline, lost in a step outside the published code; the web does not imitate it.

## Conventions that differ from defaults

- Deduplicate before splitting train/test data.
- Extract engineered features from raw email before cleanText removes information needed by extraction.
- Fit the engineered-feature scaler on training data only.
- Derive feature order and count from preprocess.BASELINE_FEATURE_NAMES (FEATURE_NAMES followed by the BASELINE_EXTRA_FEATURES groups) rather than numeric comments; a run's actual columns are its manifest settings.feature_names, because `--feature-set no_era_proxies` drops columns at vectorize time. evaluate.py finds ATTACHMENT_RULES features by name there, so a feature set must never drop a rule feature.
- Preserve concatenation order: Doc2Vec followed by scaled engineered features. analyze_feature_importance.py hardcodes DOC2VEC_DIM = 100; update it when changing embedding dimensions.
- Preserve labels 0=legitimate and 1=positive. In `--target-mode broad`, disclose that SpamAssassin spam is in the positive class; the default phishing mode drops every spam/spam_or_phishing row as outside_label_scope (train.py select_label_scope), so SpamAssassin, CEAS, Ling, TREC and Enron.csv contribute legitimate mail only.
- Preserve Windows path handling in load_data.py when changing corpus access; it supports Enron filenames with trailing dots.
- Load the raw TREC 2007 corpus (Dataset/trec07p, labels from full/index) before Dataset/phishing: while it is present, TREC_07.csv (the same corpus with headers and HTML stripped) is excluded, and loading the CSV first raises instead of double-counting. Each data/inmail.* is one message that starts with an mbox envelope line; never split it as an mbox.

## Known pitfalls

- Verify saved artifacts against current code before reporting metrics; this workspace has contained test arrays with mismatched sample counts and an outdated feature dimension.
- Do not attribute backup logs to the current version without matching code and artifacts.
- Preserve positive-class probability ROC-AUC for both CSV and ROC plots; predicted labels are used for classification metrics.
- Before repeating a costly full evaluation for provenance, inspect the existing successful evaluation log and selected run. Recompute only when evidence is missing, inconsistent or recomputation is explicitly requested.
- Do not restore num_received_hops or has_date_header to FEATURE_NAMES without reassessing source bias; their removal is documented beside FEATURE_NAMES.
