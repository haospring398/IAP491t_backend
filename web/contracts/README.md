# Shared analysis contract, version 1

`analysis.schema.json` is the exact browser/proxy/service success, failure and
active-status wire contract. JSON responses also require the matching v4 UUID
`X-Request-ID` header. Multipart is exactly one `file` part; the proxy replaces
its filename with `message.eml` and forwards a trusted UTC epoch-millisecond
`X-Analysis-Deadline`. Caller deadlines are discarded.

`transport-policy.json` is the single initial AD-5/6/7/13 profile. Its schema and
runtime consistency checks fail the frontend build/initialization on invalid
policy. MIME/token limits are recorded for the future backend; the proxy does
not implement its MIME parser. JSON response consumption is bounded by the same
whole-body byte limit. Error messages exposed by the proxy are safe policy copy.

Backend contract ownership remains with the Python/API workstream. No backend or
OpenAPI service is implemented here. Coordinate revisions to schema and policy
with that owner; never add an independent consumer profile. These initial bounds
remain unqualified assumptions until E2/E4 measurements, parser qualification,
clock-skew/deadline/reap evidence and provider ceiling checks are available.

From `web/frontend/` in the repository (or sibling `../frontend/`), run
`npm.cmd run contracts:generate` after a coordinated schema
change. Commit `lib/contracts.generated.ts`; `contracts:check` detects drift.
Types are generated by json-schema-to-typescript and AJV validates actual wire
responses separately. There are no score, filename, history or indicator fields.

## Compatibility update — 2026-10-19

The deployment-only `deadlines.handlerSeconds` ceiling was removed from the
transport policy. Update policy, policy schema, generated types and runtime
validators together; the current strict schema rejects the old property. The
version 1 wire response contract is unchanged.
